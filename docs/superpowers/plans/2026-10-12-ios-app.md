# iPhone App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an iPhone app for uni-vpn that runs the Go core and libopenconnect in-process, built and tested in CI, ready for David to sign and publish.

**Architecture:** the daemon gets a third `Tunnel` implementation, `internal/libtunnel`: libopenconnect through cgo (`internal/octunnel`) writes the tunnel to a socketpair, a gVisor netstack (`internal/netstack`) reads the other end, and the existing SOCKS server dials through the netstack. The core is a C archive (`cmd/uni-vpn-ios`) used by a SwiftUI app and its packet tunnel extension.

**Tech Stack:** Go 1.26 + cgo, libopenconnect 9.21 + OpenSSL 3.5.9, golang.zx2c4.com/wireguard/tun/netstack, Swift 6 / SwiftUI / NetworkExtension / VisionKit, XcodeGen, GitHub Actions (ubuntu-latest, macos-15).

**Spec:** docs/superpowers/specs/2026-10-12-ios-app-design.md

## Global Constraints

- Commits authored as `DavidVinu <me@davidvinu.de>`, terse lowercase messages, no trailers of any kind.
- No em dashes anywhere (code comments, docs, UI text).
- English code, comments and docs; UI text only through `locales/<lang>.json` keys (reuse `phone.*` keys from the Android app, add new keys to all six catalogs).
- Least technical user: click-only, minimal text, hints behind an info button.
- The daemon's HTTP API, `message_id`, `action` and `/api/repair` are a frozen contract.
- Desktop and Android behaviour must not change: everything new is behind the build tag `libopenconnect` or `GOOS=ios`.
- Bundle ids: app `de.davidvinu.univpn`, extension `de.davidvinu.univpn.tunnel`, App Group `group.de.davidvinu.univpn`, deployment target iOS 17.0.
- openconnect output lines that the classifier reads (`internal/tunnel/classify.go`) must be produced with the same wording by the in-process engine.

### Task 3: libopenconnect through cgo

**Files:**
- Create: `internal/octunnel/octunnel.go` (build tag `libopenconnect`), `internal/octunnel/shim.c`, `internal/octunnel/shim.h`, `internal/octunnel/trust_ios.c` (build tag `ios`), `internal/octunnel/octunnel_test.go`
- Linux: `pkg-config openconnect` (apt `libopenconnect-dev`); iOS: `CGO_CFLAGS`/`CGO_LDFLAGS` from the native build (Task 7).

**Interfaces:**
- Produces:
```go
type Options struct {
    Host, UserAgent, User, AuthGroup, UserGroup, OS string
    Password []byte
    SecondPassword string // "push" for duo_push, "" otherwise
    TOTPSecret string     // "base32:..." for totp_field, "" otherwise
    NoExternalAuth bool
    ReconnectTimeout int  // 60
    Line func(string)     // every progress and form line, like openconnect's stderr
}
type Session struct{ /* vpninfo, cmd fd */ }
func Connect(o Options) (*Session, error)        // obtain cookie + make CSTP connection; on failure the lines tell why
func (s *Session) IPInfo() (addr netip.Addr, dns []netip.Addr, mtu int)
func (s *Session) Run(tunFD int) int              // mainloop until cancelled or dead; returns openconnect's code
func (s *Session) Cancel()                        // OC_CMD_CANCEL through the cmd pipe
func (s *Session) Reconnect()                     // OC_CMD_PAUSE then resume, like SIGUSR2
func (s *Session) Free()
```
- Lines it must produce, with these exact texts where the CLI prints them (main.c): `"Login failed."` style form errors as `form->error` text, `"User input required in non-interactive mode"` when a prompt cannot be filled (not for duo's second password), `"Failed to complete authentication"` when `openconnect_obtain_cookie` fails, `"Generating OATH TOTP token code"` comes from libopenconnect itself.

**Files:**

**Interfaces:**
- Consumes: Task 1 `socks.Server.Net`, Task 2 `netstack.New`, Task 3 `octunnel`.
- Produces: `libtunnel.New(cfg tunnel.Config, log *slog.Logger, engine Engine) *Tunnel` implementing `daemon.Tunnel` (Start, WaitReady, Stop, Exited, HasExited, StoppedByUs, Classification, ReturnCode, OTPGeneratedAt, Port, StartedAt, ReadyAt). `Engine` abstracts `octunnel` so tests use a fake:
```go
type Engine interface {
    Connect(o octunnel.Options) (Session, error)
}
type Session interface {
    IPInfo() (netip.Addr, []netip.Addr, int)
    Run(tunFD int) int
    Cancel()
    Reconnect()
    Free()
}
```
- Behaviour: Start computes the password bytes exactly like `tunnel.StdinBytes` (reuse it: build a `tunnel.Tunnel` only for `StdinBytes`, or move that function to a shared helper), picks a free port, runs Connect + netstack + `socks.NewServer(port, "", dns, log)` with `Net = stack` in a goroutine; every line goes through a `tunnel.Classifier` (same as `handleLine`); the SOCKS listener opening is "ready"; when Run returns, the SOCKS server and stack close and `Exited()` closes with the return code (0 when cancelled by us). Stop calls Cancel and waits up to grace.
